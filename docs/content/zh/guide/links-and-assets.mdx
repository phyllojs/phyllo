# 链接与资源 \{#links-and-assets\}

本页介绍页面之间的链接、外部链接和图片等资源的处理方式。

## 链接其他页面 \{#links\}

页面之间使用相对文件路径链接：

```mdx
[安装说明](./guide/installation.mdx)
```

路径相对于当前文件。构建时，Phyllo 将 `.md` 和 `.mdx` 链接改写为页面地址，不需要手动填写最终网址。从 `content/getting-started.mdx` 出发，上面的链接对应 `/guide/installation`。

移动或重命名页面后，指向它的链接需要同步更新。

## 链接到章节 \{#anchors\}

在文件路径后附加锚点，可以跳转到目标页面的指定小节：

```mdx
[准备环境](./guide/installation.mdx#prerequisites)
```

目标页面需要包含对应锚点，例如 `## 准备环境 \{#prerequisites\}`。锚点的写法见 [文章写作](./writing.mdx#anchors)。

## 外部链接 \{#external-links\}

外部网站使用完整网址：

```mdx
[Phyllo 仓库](https://github.com/phyllojs/phyllo)
```

以 `/`、`#` 或 `?` 开头的地址会原样保留，不会被改写。

## 插入图片 \{#images\}

图片使用 Markdown 语法，路径同样相对于当前文件：

```mdx
![项目的预览界面](./images/preview.png)
```

方括号内是替代文本，供屏幕阅读器读取，图片无法加载时也会显示这段文字。

## public 目录 \{#public\}

`public/` 用于存放固定地址的文件，例如标签页图标、字体和其他系统引用的图片。`public/logo.svg` 对应的地址是 `/logo.svg`，文件原样复制到输出目录。引用这些文件时使用根路径写法，例如 `/logo.svg`。

随页面引用的图片建议放在 `content/` 中，这类资源会经过构建处理，见下一节。

## 资源如何构建 \{#assets\}

相对路径引用的图片和附件会随页面一起构建：

- 文件复制到输出目录，文件名带有内容哈希，便于浏览器长期缓存。
- 页面中的引用被改写为新地址。
- 同一份文件在多处引用时共用同一个副本。

引用路径相对于源文件所在的目录。移动文章时需要连同资源一起移动，或者同步修改引用。组件中也可以直接导入资源，打包流程会处理这些引用。

地址固定且不需要页面引用的文件，放在 `public/` 中。

## 链接检查 \{#link-checks\}

以下情况会导致构建失败：

- 相对链接指向内容目录之外的文件。
- 同一页面内出现重复的标题锚点。
- 引用的图片或其他资源文件不存在。

其他构建错误见 [故障排查](../about/troubleshooting.mdx)。

页面顶部信息的写法见 [页面信息](./frontmatter.mdx)。
