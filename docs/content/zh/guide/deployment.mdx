# 部署 \{#deployment\}

文章写好后，先构建网站，再将生成的文件部署到托管服务。Phyllo 使用 Bun 构建，产物是静态文件，托管时不需要运行 Bun。

## 构建网站 \{#build\}

在项目目录中运行构建命令：

```sh
bun run build
```

终端显示 `Built … pages` 表示构建完成，产物位于 `dist/`。文章修改后需要重新构建，并上传新的 `dist/`。

## 输出结构 \{#output\}

页面地址与输出文件一一对应：

| 页面地址              | 输出文件                  |
| --------------------- | ------------------------- |
| `/`                   | `index.html`              |
| `/getting-started`    | `getting-started.html`    |
| `/guide/installation` | `guide/installation.html` |

页面资源位于 `_phyllo/` 目录，构建时自动处理引用。资源文件名带有内容哈希，可以放心为它们配置长期缓存。

## 托管要求 \{#hosting\}

页面地址不带 `.html`，因此托管服务需要支持无扩展名地址（clean URLs）。访问 `/getting-started` 时返回 `getting-started.html`，访问根路径时返回 `index.html`。

站点内的链接从 `/` 开始，因此需要部署到域名根路径。例如 `https://docs.example.com/`。`/my-project/` 这样的子路径无法访问。

将所有请求重写到首页会导致文章无法访问。上传时应保留 `dist/` 中的完整目录结构。

## 自动构建 \{#continuous-deployment\}

如果文章保存在代码仓库中，支持 Bun 的托管平台可以在提交后自动构建。工作目录设为站点根目录，其他设置如下：

| 设置     | 值                              |
| -------- | ------------------------------- |
| Bun 版本 | 1.4 或更高版本                  |
| 安装命令 | `bun install --frozen-lockfile` |
| 构建命令 | `bun run build`                 |
| 发布目录 | `dist`                          |

`bun run build` 使用项目内安装的命令行工具，托管平台不需要全局安装。`--frozen-lockfile` 按锁文件安装依赖，依赖声明与锁文件不一致时会报错。`bun.lock` 需要随仓库提交。

仓库包含多个项目时，将工作目录指向站点所在目录。

## 上线后检查 \{#verify\}

发布后确认以下内容：

- 首页和文章能否通过地址直接访问。
- 文章刷新后是否正常显示。
- 导航、图片和搜索结果是否指向正确位置。
- 使用 MDX 的交互组件是否正常响应。
- 主题提供的语言菜单能否跳到对应译文。

如果首页正常而文章返回 404，先检查无扩展名地址的配置。如果图片缺失，检查是否上传了完整的 `dist/`。其他问题见 [故障排查](../about/troubleshooting.mdx)。

部署完成后，可以继续阅读 [主题概述](../themes/overview.mdx)，了解主题的安装与更换。
