# Writing a theme \{#theme-development\}

A theme is a React component package that default-exports a layout component deciding page structure. This page starts from the template generated by the command line tool and writes a layout that lists articles and displays the body.

For customizing an existing theme, see [Customizing themes](./customization.mdx). The examples require basic knowledge of TypeScript and React.

## How a theme is structured \{#structure\}

A theme is an npm package. The `name` field in `package.json` declares the package name, and `exports` points to the entry file. The entry default-exports the layout component, and Phyllo renders it to generate pages.

A theme depends only on `phyllo` and `react`, not on build tools or command line tools.

## Creating the theme package \{#create-the-package\}

Run this in the site directory:

```sh
phyllo theme themes/my-theme --package phyllo-theme-local
```

The command only creates source files. It does not switch the site's theme. The generated directory looks like this:

```text
themes/my-theme/
├── src/
│   └── index.tsx
├── package.json
└── tsconfig.json
```

## Writing the layout \{#layout\}

The layout is a React component that returns the page structure. It receives the current page's body through `children` and reads site data through Hooks:

- `useSite()` reads the site name, description, and HTML language.
- `usePage()` reads information about the current page.
- `usePages()` reads the article list without loading article bodies.

`themes/my-theme/src/index.tsx` can be written as:

```tsx
import { HeadResources, usePage, usePages, useSite } from 'phyllo';
import type { ReactNode } from 'react';

export default function Layout({ children }: { children?: ReactNode }) {
  const site = useSite();
  const page = usePage();
  const pages = usePages().filter(article => article.hasContent);
  const description = page.description ?? site.description;

  return (
    <html lang={site.lang ?? 'en'}>
      <head>
        <meta charSet="utf-8" />
        <meta name="viewport" content="width=device-width, initial-scale=1" />
        <HeadResources />
        <title>{page.title}</title>
        {description !== undefined && (
          <meta name="description" content={description} />
        )}
      </head>
      <body>
        <header>{site.title}</header>
        <main>
          {page.hasContent ? (
            children
          ) : (
            <ul>
              {pages.map(article => (
                <li key={article.url}>
                  <a href={article.url}>{article.title}</a>
                </li>
              ))}
            </ul>
          )}
        </main>
      </body>
    </html>
  );
}
```

`children` is the current page's body, and `page.hasContent` tells whether a page has a body. The example shows the body on article pages and lists articles on the home page, which has no body.

A theme is an ordinary React component and can return full HTML, a partial JSX fragment, or `null`. Phyllo renders whatever the component returns. It does not require specific tags or wrap the output in a document structure. Browsers handle omitted document tags while parsing HTML, and when the component returns `null`, the page has no theme content.

The example writes `<html>`, `<head>`, and `<body>` explicitly to make it easy to set page attributes and metadata. `HeadResources` outputs theme styles, page data, the client script, and tags from the head configuration. A theme that renders `<html>` or `<head>` must render it inside `<head>`. For a theme that returns a fragment or nothing and has no `<head>`, Phyllo outputs these resources before the content, and the browser parses them into `<head>`.

The theme outputs the page title and description, and values from `page` and `site` can be used directly. `site.lang`, `site.title`, and `site.description` come from the site configuration and act as defaults when the theme does not define matching values.

## Enabling it in the site \{#connect-to-the-site\}

Add the theme to the site dependencies:

```json
{
  "dependencies": {
    "phyllo-theme-local": "workspace:*"
  }
}
```

Run `bun install`, then change `theme` in the site configuration to the theme package name:

```ts
theme: 'phyllo-theme-local',
```

After you start the dev server, the home page shows the site name and the article list. Click a title to read the body.

## Styles and interactions \{#styles-and-interaction\}

Theme styles go in `themes/my-theme/src/style.css` and are imported in the layout entry:

```ts
import './style.css';
```

`phyllo/client` provides types for CSS imports. The generated `tsconfig.json` already declares them. Keep them when you modify the TypeScript configuration.

Images and other assets can also be imported. The import result is a URL with a content hash:

```tsx
import logo from './logo.svg';

<img src={logo} alt="Logo" />;
```

Asset types also come from `phyllo/client`, and server rendering, the build output, and the dev client use the same URL. Phyllo handles image imports, and explicit loaders such as `with { type: 'text' }` do not apply to image extensions.

A theme's `package.json` can also define `imports` aliases that start with `#`. When an alias points to code or MDX, condition branches are selected by the run target. When an alias points to an image, keep the image extension and do not configure condition branches on the alias. Image imports always resolve for the Bun runtime, so server rendering, the dev client, and the build output all take the `bun` branch.

Paragraphs, headings, and lists generated from Markdown are ordinary HTML elements, so you can style them with CSS. Code blocks already have syntax highlighting, and the theme can adjust their background, spacing, and typography.

Interactive components in a theme are written the same way as MDX components. Components also run at build time, so code that accesses browser objects must go in an event callback or a `useEffect`. See [Code in the browser](../guide/writing.mdx#browser-code).

In dev mode, editing an MDX file, an asset it references, or the compilation configuration can remount components in the module and reset their internal state. To keep state across updates, put the component in its own TSX file.

The dev server watches the theme's real source paths for updates. Workspace themes and local themes keep their source outside `node_modules`, so pages update when you edit them. A theme installed in `node_modules` does not support hot updates from source while running. Restart the dev server after modifying or upgrading it.

## MDX module types \{#mdx-module-types\}

The generated `.phyllo/mdx.d.ts` declares a `frontmatter` named export for every `.mdx` file, with types from `phyllo/types` and no dependency on a UI framework. Importing MDX components in TSX also needs component types. Install `@types/mdx`, add `mdx` to `types` in `tsconfig.json`, and add a module augmentation declaration for your framework. Newly generated sites already include these settings. Existing sites or standalone themes must add them.

React 19 types no longer provide the global `JSX` namespace, while `@types/mdx` still references it. For React projects, add:

```ts
// mdx-jsx.d.ts
import * as React from 'react';

declare module 'mdx/types.js' {
  export import JSX = React.JSX;
}
```

`@types/mdx` also declares `*.md`, `*.markdown`, `*.mdown`, `*.mkdn`, `*.mkd`, `*.mkdown`, and `*.ron`. These extensions can be imported in TypeScript, but that does not mean Phyllo compiles them. `.md` is compiled as Markdown and has no body expressions or frontmatter export.

## Content components \{#content-components\}

Besides the default-exported layout, a theme can export named components for articles to import with MDX:

```tsx
export function Callout({ children }: { children?: ReactNode }) {
  return <aside className="callout">{children}</aside>;
}
```

Articles can use them after importing. The theme is responsible for their styles and usage notes.

## Head tags \{#head-tags\}

Icon or script tags output by the theme are kept, and tags in the site configuration `head` are appended directly. Both are output together. Phyllo does not merge or deduplicate them. For the rules, see [Head tag appending](../reference/configuration.mdx#head-appending).

For the full fields of the Hooks, see the [Hooks reference](../reference/hooks.mdx).
